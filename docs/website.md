# 위클리랩 홈페이지 개발 안내

위클리랩(Weekly Lab)의 서비스와 실제 작업 경험을 소개하는 홈페이지 초안입니다.
HTML과 CSS만 사용하며, 패키지 설치나 빌드 없이 열 수 있습니다.

## 미리 보기

저장소 루트의 `index.html`을 브라우저로 열면 됩니다. macOS에서는 저장소 루트에서 다음 명령을 사용할 수 있습니다.

```sh
open index.html
```

로컬 서버로 확인하려면 저장소 루트에서 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 <http://127.0.0.1:8000>에 접속합니다. 종료는 `Ctrl+C`입니다.

## 파일

- `index.html`: 제공 서비스, 구축/개발 사례, 의뢰 절차, 상담 CTA와 사업자 정보
- `styles.css`: 색상, 타이포그래피, 그래픽, 모바일 레이아웃
- `assets/weeklylab-logo.png`: 제공된 위클리랩 로고 원본
- `assets/weekly-school-preview.png`: 위클리스쿨 공개 소개 페이지의 화면 이미지

## 디자인 방향

기존 `위클리랩_로고.png`와 `명함 시안1.png`를 확인해 브랜드 방향을 맞췄습니다.
로고의 주요 픽셀 색상은 보라색 `#332C85`, 노란색 `#F9B53D`, 배경색 `#FAF9F4`입니다.
이는 원본 PNG에서 읽은 색상이며 별도의 공식 색상 규정은 확인하지 않았습니다.

원본 로고를 그대로 보관하고, SVG의 표시 영역으로 주변 여백만 제한해 사용합니다.
명함의 얇은 보라색 선과 끝점, 넓은 여백을 홈페이지 그래픽에 반영했습니다.
업무용 이메일을 상담 연락처로 사용합니다. 전화번호와 주소는 공개하지 않습니다.
외부 폰트, 외부 이미지 요청, JavaScript 없이 동작합니다.

## 문구와 공개 범위

첫 화면은 반복 업무 전산화, 외부 서비스 연동, 기존 시스템 개선을 중심으로 구성했습니다.
구축/개발 사례는 위클리랩에 맡길 수 있는 기능과 업무를 중심으로 설명합니다.
회사명이나 고용 및 참여 형태를 나열하지 않고, 구현한 기능과 해결한 문제를 보여줍니다.
로컬 코드와 개인 Git 기여, 업무 기록, 기존 포트폴리오를 대조한 조사 결과를 바탕으로 작성했습니다.

| 사례 | 소개 범위 |
|---|---|
| 위클리스쿨 | 운영 중인 출석 관리 서비스. 이미지는 공개 소개 페이지이며 실제 서비스로 연결 |
| 로그인과 알림, 운영 통계 | 소셜 로그인, 메시지 발송, 파일 저장과 통계 API 구현 |
| 홈페이지와 콘텐츠 관리 | 홈페이지와 관리자 화면 구축 진행. 운영 배포와 전체 검수 완료로 표현하지 않음 |
| 재고와 발주 자동화 | 발주 판단, 거래명세서, 엑셀 처리와 재고 정합성 |
| 검색 시스템 이전과 개선 | API 이전, 데이터 검증과 알림 처리 개선 |
| 인증과 물류 서비스 연동 | 인증, 외부 API 연동과 데이터베이스 및 서버 이전 |
| 데이터 취합과 보고서 자동화 | 주기적 수집, 이메일, 엑셀 보고서와 기존 시스템 전환 |

과거 회사의 코드, 내부 문서, 계약 내용과 제3자의 연락처는 포함하지 않습니다.
검증되지 않은 성능 개선율, 비용 절감액, 서비스 규모와 인증 성과 수치도 사용하지 않습니다.
구체적인 구현 자료가 없는 비용 절감 경험은 개별 성공 사례로 싣지 않았습니다.
일하는 방식에는 구축 이후의 운영 비용을 함께 살피는 관점을 반영했습니다.

## 의뢰 진행 절차

상담과 현황 파악, 기능 정리와 시안 확인, 견적과 계약, 개발과 중간 확인, 검수와 보완, 공개와 운영 인계의 6단계로 안내합니다.
기존 홈페이지 구축의 기능명세와 시안 확인 기록, 계약 및 자료 협의, 검수와 인계 절차를 참고했습니다.
개별 프로젝트의 금액과 날짜, 계약상 세부 조건은 일반적인 서비스 약속으로 옮기지 않았습니다.
공개와 검수, 교육의 실제 순서는 프로젝트에 맞춰 조율하며, 예정된 인계 절차를 이미 마친 실적으로 표현하지 않습니다.

## 배포

위클리스쿨과 같은 인스턴스에서 GitHub Actions의 SCP 전송과 Nginx로 서비스합니다.
기본 주소는 `https://weekly-lab.com`이며, `www.weekly-lab.com`도 지원합니다.
정적 파일 경로는 `/usr/share/nginx/weekly-lab`으로 분리합니다.
DNS, GitHub Secrets, 인증서 발급과 Nginx 적용 순서는 [배포 안내](../deploy/README.md)를 참고합니다.
설정 파일은 준비되어 있으며 실제 서버 적용과 공개 확인은 별도로 진행해야 합니다.
